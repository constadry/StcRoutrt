# StcRoutrt

Маршрутизатор: регистрирует шаблоны вида `/foo/{id:guid}/bar/` и по строке `/foo/3f25.../bar` вызывает нужный обработчик с уже разобранными параметрами.

```csharp
var r = new Router();
r.RegisterRoute<int, int>("/sum/{a:int}/{b:int}/", (a, b) => Console.WriteLine(a + b));
r.Route("/sum/1/2"); // 3
```

## Как устроено

Все маршруты хранятся в дереве (trie). Один узел дерева соответствует одному сегменту пути между `/`.

У каждого узла есть:
- `Static` — словарь детей для обычных сегментов (`foo`, `bar`);
- `Params` — словарь детей для параметров, ключ — тип из шаблона (`"int"`, `"guid"`, `"datetime"`);
- `Handler` — обработчик, если на этом узле заканчивается маршрут.

Например, после регистрации `/foo/bar/{p:int}/`, `/foo/{id:guid}/bar/` и `/foo/{date:datetime}/bar/`:

```
(корень)
 └─ foo
     ├─ bar
     │   └─ {int}        → обработчик
     ├─ {guid}
     │   └─ bar          → обработчик
     └─ {datetime}
         └─ bar          → обработчик
```

### Регистрация

1. Шаблон режется по `/`.
2. Идём от корня: обычный сегмент ищем в `Static` (нет — создаём), сегмент `{имя:тип}` уходит в `Params[тип]`.
3. На последнем узле сохраняем обработчик. Если он там уже есть — это дубль, бросаем `ArgumentException`. Дубль — это тот же путь с теми же типами на тех же местах.

Типизированные `RegisterRoute<T1>` и `RegisterRoute<T1, T2>` один раз заворачивают `Action` в общий обработчик `Func<string[], bool>`. Он разбирает строки через `T.TryParse` (`IParsable<T>`, `InvariantCulture`) и возвращает `false`, если значение не подошло по типу. `Action` вызывается только когда все параметры разобраны.

Регистрация идёт под `lock`, поэтому маршруты можно регистрировать из нескольких потоков.

### Параметры по имени

Значения передаются в обработчик по имени, а не по порядку в пути:

```csharp
r.RegisterRoute<int, int>("/{b:int}/bar/{a:int}/", (a, b) => ...);
r.Route("/1/bar/2"); // a = 2, b = 1
```

При регистрации один раз строится массив `map`: для каждого параметра лямбды — его позиция в пути. Для примера выше имена в пути `["b", "a"]`, параметры лямбды `(a, b)`, значит `map = [1, 0]`. При вызове обработчик берёт `args[map[0]]` для `a` и `args[map[1]]` для `b`. Если имени параметра лямбды нет в шаблоне, `RegisterRoute` сразу бросает исключение.

### Поиск (`Route`)

Строка режется по `/`, и мы идём по дереву рекурсивно, с откатом:

1. Сначала пробуем точное совпадение в `Static`.
2. Если эта ветка не привела к результату — по очереди пробуем каждый узел из `Params`, запоминая значение сегмента как параметр.
3. Дошли до конца пути — вызываем `Handler`. Если он вернул `false` (параметр не прошёл `TryParse`), откатываемся и пробуем следующую ветку.

Так `/foo/3f2504e0-.../bar` попадёт в маршрут с `guid`, а `/foo/2026-10-17/bar` — в маршрут с `datetime`: в чужой ветке `TryParse` вернёт `false`. Если подходят несколько веток (например, `string` и `int` на одном месте), срабатывает первая подошедшая.

Если ничего не нашлось, `Route` пишет «Маршрут не найден», а если путь совпал, но параметры не подошли по типу — «найден, но параметры не прошли проверку». Исключений `Route` не бросает.

## Почему хорош при большой нагрузке

- **Скорость не зависит от числа маршрутов.** На каждый сегмент пути — одно обращение к словарю. Для `/foo/bar/5` это три шага, будь в роутере 10 маршрутов или 10 000. Перебора всех шаблонов и регулярных выражений нет. Откат срабатывает только там, где на одном месте зарегистрированы параметры разных типов, и перебирает лишь их.
- **Тяжёлая работа сделана при регистрации.** Шаблон разбирается один раз, обёртка с парсингом и массив `map` для имён строятся один раз. При вызове остаётся пройти по дереву и сделать `TryParse`.
- **Чтение без блокировок.** `Route` ничего не блокирует, а `ConcurrentDictionary` читается без локов, поэтому тысячи потоков могут вызывать `Route` одновременно и не ждут друг друга.
- **Регистрация потокобезопасна.** `RegisterRoute` выполняется под `lock`, так что одновременная регистрация не испортит дерево и не пропустит дубль. Регистрация редкая, поэтому lock на скорость вызовов не влияет.
- **Нет исключений на плохом вводе.** Неверный параметр (`/foo/bar/abc` для `int`) даёт `TryParse == false`, а не `FormatException`. Исключения в .NET дорогие, и под нагрузкой это важно.
